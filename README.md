# Hiver SDE Intern Take-Home — Spotify Support Agent

This project builds a support agent for **Spotify** using the Customer Support on Twitter dataset.

The agent:
1. classifies an inbound customer tweet into a compact Spotify-specific intent taxonomy;
2. retrieves historically similar Spotify support conversations;
3. drafts a grounded reply;
4. decides AUTO vs ESCALATE with a reason;
5. evaluates intent classification, routing, reply quality, and LLM-judge/human agreement.

Dataset: Kaggle Customer Support on Twitter:
https://www.kaggle.com/datasets/thoughtvector/customer-support-on-twitter

The dataset contains `tweet_id`, `author_id`, `inbound`, `created_at`, `text`,
`response_tweet_id`, and `in_response_to_tweet_id`. The links between tweet IDs
allow conversations to be reconstructed.

## 1. Setup

Python 3.10+ recommended.

```bash
python -m venv .venv
# Windows:
.venv\Scripts\activate
# macOS/Linux:
# source .venv/bin/activate

pip install -r requirements.txt
```

For LLM features:

```bash
copy .env.example .env
```

Put your API key in `.env`.

## 2. Get the dataset

Download `twcs.csv` from the Kaggle dataset and place it here:

```text
data/twcs.csv
```

Do not commit the full dataset.

## 3. Build a Spotify sample

```bash
python scripts/prepare_data.py --input data/twcs.csv --brand spotify --max-examples 30000
```

This produces:

```text
artifacts/spotify_examples.jsonl
artifacts/spotify_retrieval.jsonl
artifacts/golden_template.jsonl
```

The retrieval corpus excludes the golden examples once you label and assign them.

## 4. Create the golden set

Open:

```text
artifacts/golden_template.jsonl
```

Label 200 examples yourself.

Required fields:

```json
{
  "id": "...",
  "customer_message": "...",
  "intent": "...",
  "expected_route": "AUTO",
  "reference_reply": "..."
}
```

Do NOT use an LLM to create the final labels. The point is to have a human-labelled evaluation set.

Then save it as:

```text
artifacts/golden_set.jsonl
```

## 5. Run the agent

```bash
python -m src.pipeline --message "I was charged twice for Premium"
```

If OPENAI_API_KEY is available, the final reply is generated by the LLM.
Without it, the system still runs using retrieval and a deterministic fallback.

## 6. Run evaluation

```bash
python -m evaluation.run_all
```

This evaluates:
- majority baseline
- TF-IDF + logistic regression baseline
- zero-shot LLM classifier, if an API key is configured
- retrieval/LLM agent
- escalation decisions

## Intent taxonomy

The initial Spotify taxonomy is deliberately compact:

- billing_payment
- refund
- subscription_cancel
- subscription_plan
- account_login
- account_security
- premium_not_working
- playback_problem
- app_technical_problem
- playlist_music_problem
- family_student_plan
- gift_code
- feature_request
- general_complaint
- other

You should revise this taxonomy after inspecting the sampled Spotify data. The taxonomy is a hypothesis, not ground truth.

## Important evaluation design

Golden examples must be held out from the retrieval corpus. Otherwise an identical historical conversation can be retrieved and inflate results.

The primary classification metric is Macro-F1, not just accuracy, because intent classes are imbalanced.

Reply quality should be judged separately from intent classification.

## LLM judge

`evaluation/llm_judge.py` scores replies on:
- relevance
- groundedness
- correctness
- helpfulness
- tone
- conciseness

For judge validation, manually score a subset of generated replies in:

```text
artifacts/human_judge.csv
```

and run:

```bash
python evaluation/judge_agreement.py
```

This compares human and LLM scores. The LLM judge is not treated as ground truth.

## What is intentionally NOT built

- live Twitter integration
- autonomous refunds or account changes
- multi-brand support
- a production vector database
- a fancy UI

The assignment is primarily an evaluation exercise, so reproducibility and evidence are prioritized over UI.

## Reproducibility

For the headline experiment, use the provided sampled artifacts rather than the entire 3M+ tweet dataset. This keeps evaluation fast.
